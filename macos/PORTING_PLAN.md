# macOS port: plan

Decided: macOS 26 minimum; icon generated from the project SVG (`scripts/make_icon.sh`); typed error enum across the bridge;
`NSDocument` for the shell only (core stays the source of truth: `read(from:)`/`data(ofType:)` delegate to core); syntax
colours from the existing theme generator extended to write a Swift table; no remote/SFTP support (Known limitation); one
window per document, automatic tabbing off; tag-triggered release job attaches the DMG. SwiftPM + bundling script, UniFFI bridge, WKWebView preview from core HTML, Apple silicon only, ad-hoc
signed DMG from GitHub Actions (`.github/workflows/macos.yml`). Each step below ends with something that builds in CI.
No decisions are open at the moment.

1. **CI skeleton (done, unverified on a Mac).** Workflow, `scripts/build_core.sh`, `scripts/package.sh`, UniFFI crate
   with one function, placeholder SwiftUI window. Goal: first green run and a DMG that opens.
2. **Bridge the `Document`.** UniFFI `Object` wrapping `core::Document`: text, path, dirty, encoding, line ending,
   word/char count, open/save/save_as, `set_text` returning `bool`, `external_change`. Conversion only; tests in core.
3. **Document app shell.** `NSDocument` shell, one window per document (no tabs): Open/Save/Save As,
   recent files, unsaved-changes prompt, window title with edited dot, open-by-path from Finder (`Info.plist` document types).
4. **Editor view.** `NSTextView` (TextKit 2) in an `NSViewRepresentable`, bound to the core buffer: undo, find bar
   (`NSTextFinder`), line wrap, tab handling, font setting.
5. **Syntax highlighting + themes.** Apply core's highlight output as text attributes; map the existing theme families
   (Breeze, Atom One, Catppuccin, GitHub, Solarized) and light/dark following the system appearance.
   Colours come from `macos/Sources/Markite/Palette.swift`, generated by `python3 macos/tools/gen_macos_data.py` (same KDE theme source as the GNOME generator).
6. **Preview.** `WKWebView` showing core's rendered HTML (as the GNOME frontend does), JavaScript disabled for document
   content, links and raw HTML kept neutralised, theme CSS, fonts. View modes: editor / split / preview.
7. **Scroll sync + minimap + line gutter.** Use `blocks::line_to_block` / `block_to_line` and `minimap::lines`;
   gutter via `NSRulerView` or TextKit line-number fragments.
8. **Status bar, menus, toolbar.** Standard macOS menu bar (File/Edit/View/Window/Help), toolbar items for view mode,
   status bar with path, encoding, line ending, counts; keyboard shortcuts with Command.
9. **Settings and file handling.** `Settings` scene (`@AppStorage`): appearance, theme, fonts, wrap column, preview width,
   encoding/line-ending conversion; external-change polling (`checkExternal` equivalent, reload/conflict), 100 MB cap,
   encoding conversion. Sandbox is off, so plain paths; remote/SFTP files are not supported (Known limitation).
10. **Polish and release.** Accessibility labels, localisation, About panel, app icon, `verify.sh` (bundle layout,
    ad-hoc signature, launches headless), README/ARCHITECTURE/BUGS_AND_FINDINGS updates, version in `set_version.sh`,
    optional tag-triggered release job that attaches the DMG.
